# fix: `^` を Excel の優先順位で計算する (#82)

## 何が起きていたか

`caretToPow` は `^` を `**` に置き換えるだけだった。

- `-2^2` は JS では `-2**2` になり、文法の誤りで `#ERROR!`（Excel は 4）
- `2^3^2` は JS の `**` が右から計算するので 512（Excel は左からで 64）
- 文字の中の `^` も `**` に変わっていた（`="a^b"` が `a**b`）

## 直し方

`caretToPow` で式を字句に分け、`^` のつながりごとに組み立て直す。

- 単項の符号は `^` より先に結び付ける。符号の付いた底や指数は括弧で囲む（`-2^2` → `(-2)**2`）
- つながりは左から括弧を付ける（`2^3^2` → `(2**3)**2`）
- 符号が二つ以上続くときは空白でつなぐ。JS は `--` を減らす演算子として読むため（`--2^2` → `(- -2)**2`）
- つながりの外は、書いたままの文字を残す。`^` の無い式の挙動は変えない
- 文字の中の `^` には触れない

## 範囲外

- つながりの外の `--`（`=--2`、`=--A1`）は今も `#ERROR!`。`^` と関係ないので、別に直す

## 確かめたこと

- Excel の優先順位で書いた参照用の計算器と、作った式で照らし合わせるテスト（種を表示する。`CARET_SEED` で再現できる）
- 字句に分けて元に戻すと、入力と同じ文字になるテスト
- 古い実装と並べて、エンジンを通した結果を比べた。`^` を含まない式では、すべて同じ結果になった。`^` を含む式の差は、すべて直したい場合（符号の付いた底や指数、つながり、文字の中の `^`）だった
- 実装をわざと壊すと（右からの計算に戻す、括弧を外す、符号を空白なしでつなぐ、エスケープを無視するなど）、どれもテストが落ちる
