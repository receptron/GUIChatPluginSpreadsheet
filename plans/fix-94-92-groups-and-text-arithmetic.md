# fix: 括弧の中の比較（#94）と、文字を計算に入れたとき（#92）

## 原因

評価器は、式を JS の式に書き換えて評価する。

- 括弧の中に比較があると、`&` の道も比較の道も外側しか見ないので、式の文字のまま返っていた（`=("a"="b")&"x"`）
- 計算の記号の隣の文字は、JS では `+` でつながり、`*` では NaN になる（`=("a"&1)+1` が a11、`=0*("a"&1)` が #DIV/0!）

## 直したこと

- `evaluator.ts` の `withGroupsEvaluated`：関数の呼び出しを値に置き換えた後、一番外側の括弧のまとまりを、それぞれ式として計算し、値に置き換える
  - 名前のすぐ後の括弧（`A1(2)` のような崩れた形）は残す
  - 参照だけの括弧は残す（#127 の空のセルの見分けのため）
  - 範囲を含む括弧も残す
- `textArithmetic.ts`（純粋な関数）の `textOperandsAsNumbers`：計算の記号（`+ - * / ^`）の隣の文字を、数として読めればその数、読めなければ #VALUE! にする。`&` や比べる記号の隣の文字は、そのまま残す

## テスト（`tests/engine/test_groupsAndTextArithmetic.ts`）

- `textOperandsAsNumbers` の例
- #94・#92 の表、括弧の値、参照だけの括弧、名前の後の括弧
- 数の文字・読めない文字を計算に入れたとき、つなぐ・比べるのは今のまま
- 生成した式：文字で書いた計算が、Excel の決まりで求めた答えと同じ
- 生成した式：括弧の中の比較をつないだ答えが、`IF(…,"TRUE","FALSE")` をつないだ答えと同じ（種を表示する。`GROUPS_SEED`）
