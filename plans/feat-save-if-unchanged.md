# feat: 表の保存を、読んだ版から変わっていないときだけ書く (#86)

## 何が起きていたか

`saveSpreadsheet` の dispatch は、ファイルを無条件に上書きしていた。#79 で画面はファイルの変更を読み直すようになったが、変更の知らせが届く前や、知らせを取りこぼしたときに画面が保存すると、ほかの書き手（エージェントや別の画面）の書き込みが黙って消えた。

## 決めたこと

- 約束はプラグインの中で閉じる。dispatch はこのプラグインのコード（`executeSpreadsheetDispatch`）がホストの `files.artifacts`（`read` / `write` / `exists`）で動かしているので、ホストを変えずに済む。MulmoTerminal は dispatch を `pluginCore.execute` に送っている。MulmoClaude は表のプラグインを自分のリポジトリに別に持っていて、このパッケージを使っていない
- 版はファイルの文字の SHA-256（`contentVersion`）。`mtime` は書き込みの粒度や時計に左右されるので使わない
- `loadSpreadsheet` は `version` を返す。`saveSpreadsheet` は省略できる `baseVersion` を受け取り、ファイルがその版のときだけ書く。違えば書かず、今の `sheets` と `version` を `conflict: true` で返す。`baseVersion` の無い保存は、今までどおり書く
- 同じファイルへの保存は、パスごとの直列の処理で、読む・比べる・書くを一続きにする
- 画面は、画面に出している版だけを保存のもとにする（最初に読んだとき、知らせを受けて反映したとき、ぶつかったあとに選んだとき）。知らせを受けても保留した（JSON の編集欄に未適用の編集がある）ときは版を進めない
- ぶつかったら知らせを出し、「保存されている内容を使う」「自分の編集で上書きする」を選んでもらう。選ぶ前にファイルがまた変わったら、知らせの持つファイルの内容を新しくする

## 残るすき間

`files.artifacts` に「比べてから書く」を一度に行う操作が無いので、プラグインを通らない書き込み（エージェントの直接の書き込み）が、保存の「比べる」と「書く」のあいだに入ると防げない。MulmoTerminal では、エージェントは表のファイルを直接書かない（receptron/mulmoterminal#3094）。

## 確かめたこと

- `contentVersion` が `node:crypto` の SHA-256 と一致する
- 条件付きの保存の各場合（版が同じ・違う・版なし・ファイルが無い・今のファイルが表でない）、同じ版をもとにした 2 つの保存を同時に送ると片方だけ書かれる、エージェントが書いたあとの保存は断られる
- 作った入れ違い（2〜4 の画面がそれぞれ何回も保存し、ぶつかったら版を取り直す）で、書かれた保存はどれも、書く直前のファイルがそのもとにした版だった（種を表示する。`SAVE_VERSION_SEED` で再現できる）
- `sheetSession`：保存のもとにする版は、保存を並べた時点ではなく実行する時点で読む。ぶつかった保存や失敗した保存は版を進めない
- 実装をわざと壊すと（直列の処理を外す、比べない、版なしでも比べる、ファイルが無くても断る、など）、どれもテストが落ちる
- 画面：本物の View を、作り物の runtime（このパッケージの dispatch とメモリの上のファイル）で Chrome で動かし、編集の保存、知らせのあるエージェントの書き込みの反映、知らせの無い書き込みのあとの編集が断られて知らせが出ること、2 つのボタンそれぞれ、選ぶ前にまた書かれた場合を確かめた
