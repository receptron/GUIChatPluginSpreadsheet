# fix: IFS の条件を、ほかと同じ Excel の比べ方で比べる (#93)

## 何が起きていたか

`IFS` の条件は `condition.ts` の `applyOperator` が比べていて、`=` は `===`（大文字小文字を区別）、並べ方は `localeCompare`、真偽値は並べない、文字と数の並びは `localeCompare` 任せだった。評価器の比較（#90 の `textComparison.ts`）と答えが食い違っていた。

## 直し方

- `applyOperator` は `textComparison.ts` の `applyComparison` を使う。`==` は `=`、`!=` は `<>`
- 空のセルは、条件の文字の中では `""` として入るので、相手が数なら 0、真偽値なら FALSE、文字なら `""` として比べる（Excel と同じ）。文字の `""` をわざと数と比べる場合だけは Excel とずれる
- `textComparison.ts` の文字の並べ方を、文字コードの順から、言語の並べ方（`Intl.Collator("en", { sensitivity: "accent" })`：大文字小文字は区別せず、アクセントは区別）にする。古い `IFS` の `localeCompare` の方が Excel に近かった（`"_"` は `"1"` の前、`"é"` は `"e"` と `"f"` のあいだ）

## 確かめたこと

- 古い `evaluateCondition` と並べて、作った条件で比べた。差は、文字と数・真偽値の並び、大文字小文字、空のセル、真偽値の並びだけで、どれも Excel と同じ答えになる方向
- 評価器の比較（#90 の道）も古い実装と並べた。答えが変わったのは文字どうしの並べ方だけ
- 実装をわざと壊すと（文字コードの順に戻す、アクセントを無視する、大文字小文字を区別する、空のセルの読み替えを外す、`!=` の読み替えを誤る）、どれもテストが落ちる
