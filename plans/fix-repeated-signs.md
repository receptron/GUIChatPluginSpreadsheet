# fix: 続いた符号（=--2、=1--2）を計算する (#88)

## 何が起きていたか

JS は `--` と `++` を、減らす・増やす演算子として読む。式を JS に渡すと `=--2` や `=1--2` が文法の誤りになり、`#ERROR!` になっていた。Excel は符号を一つずつ読む（`=1--2` は 3）。

## 直し方

`translateFormula.ts` に `separateRepeatedSigns` を足す。文字の中は飛ばし、同じ符号が続くところ（`--`、`++`）のあいだに空白を入れる。`evalValidatedExpression` で `new Function` に渡す直前にだけ通すので、計算できない式で返る文字は変わらない。

## 範囲外

`=--A1`（A1 が TRUE）は、計算の中の TRUE の読み方の問題で、#91 / #109 の範囲。A1 が数なら計算できる。

## 確かめたこと

- `separateRepeatedSigns` の例（文字の中、エスケープ、混ざった符号、`**`）と、エンジンを通した例
- `test_caretPrecedence.ts` の乱数のテストで、空白で区切らない続いた符号も作り、参照用の計算器と照らし合わせる
- 古い実装と並べて、作った式で比べた。答えが変わったのは、続いた符号を含み、前は計算できていなかった式だけ
- 実装をわざと壊すと（文字の中も変える、`-` だけにする、エスケープを無視する、呼び出しを外す）、テストが落ちる
