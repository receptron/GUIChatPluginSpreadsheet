# fix: 短い行を通る範囲で、行の位置がずれる（#115）

## 原因

`calculator.ts` の `collectRangeValues` は、行の長さより右の位置と、最後の行より下の位置を飛ばしていた。位置で読む読み方（`getRangeValuesRaw`、`getRangeValuesKeepingBlanks`）では範囲が短くなり、後ろの行が前に詰まる。

## 直したこと

行の外の位置は、空のセルとして読む（セルが `undefined` のまま、空のセルと同じ道を通る）。

- 数だけを読む場合：空のセルはもともと飛ばすので、答えは変わらない
- 位置で読む場合：空のセルと同じ値が入る

## 変わること

- 最後の行より下に伸びる範囲も、空のセルとして数える。`COUNTIF(A1:A100,"")` は、データの下の空の行も数える（Excel と同じ）
- 参照（INDEX・MATCH・VLOOKUP）は、空のセルを 0 として読む今の決まりのまま。行の外の位置も、書かれた空のセルと同じ答えになる
