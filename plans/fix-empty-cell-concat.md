# fix: 空のセルを & でつなぐと 0 になる (#83)

## 何が起きていたか

`getCellValue` は空のセルを `0` として返し、評価器はそれを式に差し込むので、`&` でつなぐと `0` が入った（Excel は何も入らない）。`{v: null}` のセルは、式より後ろにあると `"null"` として読まれ、`nullx` になっていた。

## 直し方

- 計算の側に `isCellEmpty(ref)` を作り、評価器の文脈（`EvaluatorContext`）に渡す。セルの場所を探す処理は `getCellValue` と同じ（`locateCell`）。表の範囲の外も空とみなす
- 「空」の判定は `isBlankCell`（`isEmptyCell` で空、かつ計算の誤りではない）。計算の誤りは `v` を持たないオブジェクトなので、`isEmptyCell` だけでは空と数えてしまう
- 評価器は、参照が `&` の項そのもの（`standsAloneInConcat`：両隣が `&` か式の端で、間は空白と括弧だけ）で、そのセルが空のときだけ `""` を差し込む。計算の中（`A1*2`、`-A1`、`A1+1`）では今までどおり `0`
- 判定は位置で行うので、同じセルが `&` の項と計算の両方に出る式（`=A1&A1+1`）も、それぞれ正しく扱う

## 範囲外

- 関数の引数の空のセル（`CONCATENATE(A1,"x")`、`LEN(A1)`）、比較（`=A1=""`）、`IF` の条件 → 別の issue
- 計算の中で、式より後ろの `{v: null}` を読むと `"null"` になる（`=B1+1`）。`getRawValue` はすべての読み取りが通るので触らない → 別の issue
- 範囲の集計が、計算の誤りのセルを飛ばす（`=SUM(A1:B1)` で A1 が `#DIV/0!` のとき 2 になる）→ 別の issue
- 空白だけのセル（`{v: " "}`）も空として扱うので、`&` では `""` になる（Excel は `" "`。前は `0`）

## 確かめたこと

- `standsAloneInConcat`・`isBlankCell` の例と、答えが組み立てから分かる式を作って照らし合わせるテスト（種を表示する。`EMPTY_CONCAT_SEED` で再現できる）
- 古い実装（main）と並べて、空のいろいろな形・0・文字・数・誤りのセルを読む式を作って比べた。答えが変わったのは、空のセルが `&` の項そのものとして出る式だけだった
- 実装をわざと壊すと（片側だけ見る、括弧を飛ばさない、誤りを空と数える、範囲の外を空としない、など）、動きが変わらない一つを除いてテストが落ちる
