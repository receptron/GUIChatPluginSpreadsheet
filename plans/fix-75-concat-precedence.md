# `&` を Excel の優先順位で計算する（#75）

評価器は `&` を JavaScript の `+` にそのまま置き換えていた。`+` と同じ強さで左から計算されるので、`"a"&1+2` は `a12` になった（Excel は `a3`）。

- `concatToSum`（`src/engine/concatPrecedence.ts`）：一番外の `&` で区切り、それぞれの部分を括弧で囲んで、`""` から始まる足し算にする。括弧の中にも同じことをする。部分が `true` / `false` だけなら、`"TRUE"` / `"FALSE"` にする。
- 比較（`=` `<` `>`）が文字の定数の外にある式と、空の部分がある式は、今までの置き換え（`replaceConcatOperator`）のまま。
- 評価器は、文字の定数が無くても `&` があればこの道を通す。`=A1&B1`（数値二つ）は、`2-3&3` のような文字のまま返ったり、足し算になったりしていた。

## 確かめたこと

- `tests/engine/test_concatPrecedence.ts`。評価器の変更だけを外すと落ちる。
- 「部品を一つずつ計算してから文字としてつなぐ」という Excel の作り方で答えを組み立て、生成した式（四則演算の部品も含む）で比べた。二つの種で一致した。
- `test_concatSafety.ts` の真偽値の期待値を `true!` から `TRUE!`（Excel と同じ）に変えた。

## まだ直していないもの

- 文字に `+` を使ったときに `#VALUE!` にすること（`=("a"&1)+0` は `a10` のまま）。
